# Data source: pysystemtrade raw-leg snapshot

- **Source**: [robcarver17/pysystemtrade](https://github.com/robcarver17/pysystemtrade), `data/futures/multiple_prices_csv/` — **raw per-contract daily prices for the three active legs** (front = `PRICE`/`PRICE_CONTRACT`, next = `FORWARD`/`FORWARD_CONTRACT`, prior = `CARRY`/`CARRY_CONTRACT`). Not a vendor continuous series: roll calendar, back-adjusted continuous closes, and front/deferred basis are all built in-project.
- **Pinned commit**: `b4a25e6e1e33a54a3ecfb45c0f6db5e2b60b84f8` (develop, 2026-07-18). Data frozen upstream at **2024-03-28** (Carver stopped publishing daily updates); re-fetches are manifest-gated, so drift = hard failure, never silent substitution.
- **Universe**: 16 CME roots (see `systematic_futures.data.venues`). Dropped vs the original 20: KC/SB/CC (no coverage upstream) and BZ (Brent legs start 2020-08, so they cannot fill the 2010–2019 develop window).
- **Consequences** (scope revision 2, 2026-09-09): OOT test window = **2022 → 2024Q1** (still contains the 2022 commodities-dominant trend regime); 2024-04 onward would be a Yahoo front-continuous "live tail" outside every decision; volume informational only; open interest dropped (rolls are calendar-based).
- **Licensing**: repo is GPL-3.0. Data files are used for private research only and never enter git (`data/` gitignored); the public cutover (if any) redistributes no raw rows. Provenance chain: Carver's barchart-based scraper → GitHub snapshot → our manifest.
- **Roll calendar semantics**: the schedule is **observed**: front flips exactly when the legs say it does (e.g., CRUDE_W rolls annually on December contracts, by design). Holiday rows (contract recorded, price null) are excluded; intraday snapshots collapse to the last priced row per day.
